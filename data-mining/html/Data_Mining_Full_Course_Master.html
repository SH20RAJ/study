Topic 1 & 2: Introduction to Data Mining & Relational Databases

Data Mining (Knowledge Discovery in Databases — KDD) is the computational process of discovering non-trivial, implicit, previously unknown, and potentially actionable patterns and models from massive datasets.

Database Query (SQL / OLTP) Data Mining (KDD / Discovery)
Retrieves exact known records matching user-specified criteria (e.g., "Find all students with $\text{CGPA} > 8.0$"). Discovers hidden, inductive relationships and associations (e.g., "Students who score high in Algorithms also excel in Compiler Design").
Deductive, exact, deterministic SQL responses. Inductive, statistical, pattern-based models with probabilistic confidence.

Topic 6: Data Mining Functionalities [UPLOADED PYQ]

Functionality Core Algorithmic Objective Illustrative Example
1. Characterization [UPLOADED PYQ] Summarizes the general properties of a target class into compact descriptions (Attribute-Oriented Induction). "Summarize the demographic profile of customers who spent $> ₹1,00,000$ last year."
2. Discrimination [UPLOADED PYQ] Compares the target class against one or a set of contrasting comparative classes. "Compare customers who buy gaming laptops vs. customers who buy standard business laptops."

4. Classification Supervised learning predicting discrete categorical class labels. "Classifying credit card transactions as Fraudulent or Legitimate."
5. Prediction (Regression) Predicts continuous real-valued numeric values. "Predicting real-estate house prices based on square footage and location."
6. Clustering Unsupervised grouping of unlabeled data points based on geometric similarity. "Customer market segmentation into 5 distinct spending behavioral clusters."
7. Outlier Analysis Detects anomalous objects that deviate significantly from normal baseline distributions. "Network intrusion detection and credit card fraud surveillance."

Topic 8 – 10: Data Objects & Attribute Types

Attribute Type Mathematical Characteristics & Valid Operations Representative Examples
1. Nominal Categorical labels, names, or codes with no meaningful rank or ordering ($=, \neq$). `Marital_Status` (Single, Married), `Color` (Red, Blue).
2. Binary Nominal attribute with exactly 2 states (`0` and `1`). Symmetric (Gender) vs. Asymmetric (Medical test positive/negative). `Smoker` (Yes/No), `COVID_Positive` (0/1).
3. Ordinal Categorical values with a meaningful ranking / order, but intervals between values cannot be measured ($<, >, =, \neq$). `Customer_Rating` (Poor < Fair < Good < Excellent), `Academic_Grade` (A, B, C, D, F).
4. Numeric (Interval) Measured on a scale of equal units; zero is arbitrary (no true zero point; addition and subtraction meaningful, ratios meaningless). Temperature in $^\circ\text{C}$ or $^\circ\text{F}$, Calendar Years.
5. Numeric (Ratio) Inherent absolute zero point (both differences and ratios are mathematically meaningful: $y = 2x$). `Salary` ($₹50,000$), `Age` (20 years), `Weight`, `Length`.

Topic 17: Data Transformation & Normalization [UPLOADED PYQ]

1. Min-Max Normalization Formula [UPLOADED PYQ]: $$v' = \frac{v - \min_A}{\max_A - \min_A} (\text{new\_max}_A - \text{new\_min}_A) + \text{new\_min}_A$$ Maps values into designated target range $[\text{new\_min}_A, \text{new\_max}_A]$ (commonly $[0.0, 1.0]$).
2. Z-Score (Zero-Mean) Normalization Formula: $$v' = \frac{v - \bar{A}}{\sigma_A}$$ Where $\bar{A}$ is the mean and $\sigma_A$ is the standard deviation. Essential when actual minimum and maximum are unknown or outliers dominate.
🏛️ [UPLOADED PYQ] Solved Problem: Min-Max Normalization of Value $400$ in Range $[200, 1000]$ to Target $[10, 20]$

Given: $v = 400, \min = 200, \max = 1000, \text{new\_min} = 10, \text{new\_max} = 20$.

$$v' = \frac{400 - 200}{1000 - 200} \times (20 - 10) + 10 = \frac{200}{800} \times 10 + 10 = 0.25 \times 10 + 10 = 2.5 + 10 = \mathbf{12.5}$$

Topic 18 & 19: Data Reduction & Discretization

Reduction Approach Core Mathematical / Statistical Techniques Key Benefits
1. Dimensionality Reduction Principal Component Analysis (PCA): Projects $d$-dimensional space onto $k$ orthogonal eigenvectors ($k \ll d$) maximizing variance. Wavelet transforms. Removes irrelevant features; mitigates Curse of Dimensionality.
2. Numerosity Reduction Parametric: Linear regression models ($y = mx + c$), Log-linear models.
Non-parametric: Histograms, Clustering, Random Sampling without replacement.		 Replaces massive raw dataset with compact mathematical surrogate models.
3. Discretization (Binning) • Equal-Width (Distance) Partitioning: Divides range into $k$ equal intervals: $W = \frac{\max - \min}{k}$.
• Equal-Frequency (Depth) Partitioning: Divides sorted values such that each bin contains $N / k$ samples.		 Converts continuous attributes into discrete intervals for Decision Trees and Association Mining.

Topic 20: Concept Hierarchy Generation [UPLOADED PYQ]

[UPLOADED PYQ — IT426 End] Concept Hierarchy Generation for Nominal Data
A Concept Hierarchy defines a sequence of mappings from a set of low-level concepts to higher-level, more general concepts: $$\text{Street} \longrightarrow \text{City} \longrightarrow \text{State} \longrightarrow \text{Country}$$ Two Primary Methods of Generation:
  1. Specification of Partial Ordering by Users / Experts at Schema Level: Explicitly defined by database administrators (e.g., `street < city < state < country`).
  2. Data-Driven Automatic Generation Based on Attribute Value Counts (Distinct Cardinality): The attribute with the largest number of distinct values is placed at the lowest level of the hierarchy, while the attribute with the fewest distinct values is placed at the top (e.g., `Country` (10 values) $>$ `State` (50 values) $>$ `City` (500 values) $>$ `Street` (50,000 values)).

Topic 21 & 22: Data Warehouse Modeling Schemas [UPLOADED PYQ]

Dimensional Schema Structural Layout & Normalization Key Advantages & Tradeoffs
1. Star Schema Single central Fact Table connected radially to completely denormalized Dimension Tables (1-join query topology). Simplest structure; blazing fast OLAP query response times. Contains data redundancy in dimension tables.
2. Snowflake Schema [UPLOADED PYQ] Dimension tables are normalized into multiple hierarchical sub-tables (e.g., `Product` splits into `Product_Category` and `Supplier`). Zero data redundancy; saves storage space. Slower query execution due to expensive multi-table relational joins.
3. Fact Constellation (Galaxy) Multiple Fact Tables (e.g., `Sales_Fact` and `Shipping_Fact`) sharing common conformed Dimension Tables (`Time`, `Item`). Models sophisticated enterprise-wide business operations across multiple departments.

Topic 23 & 24: Data Cube & OLAP Operations [UPLOADED PYQ]

The 5 Canonical OLAP Operations
  1. Roll-Up (Drill-Up): Aggregates data by climbing up a concept hierarchy or reducing dimensions (e.g., from `Day` $\rightarrow$ `Month` $\rightarrow$ `Quarter` $\rightarrow$ `Year`).
  2. Drill-Down: Navigates from summarized high-level data to detailed granular data (e.g., from `Country` $\rightarrow$ `State` $\rightarrow$ `City`).
  3. Slice: Performs a selection on a single dimension, producing a 2D sub-cube (e.g., `Time = "Q1 2026"`).
  4. Dice: Defines a sub-cube by performing a selection on two or more dimensions (e.g., `Location = {"Ranchi", "Patna"}` AND `Item = {"Laptop", "Phone"}`).
  5. Pivot (Rotate): Rotates the data axes in visualization to provide alternative multidimensional viewing angles.

Data Cube Materialization Choices ($2^n$ Cuboids) [UPLOADED PYQ]:

  • 1. No Materialization: Compute cuboids on-the-fly when requested. Zero disk overhead; extremely slow query latency.
  • 2. Full Materialization: Precompute all $2^n$ possible cuboids in the lattice. Fast query response; massive storage overhead.
  • 3. Partial Materialization (Optimal Industry Standard): Precomputes a carefully selected subset of high-frequency cuboids based on query workload and storage constraints (Greedy algorithm / PBS).

Q1. [UPLOADED PYQ] Compare Star Schema and Snowflake Schema across 4 architectural parameters. (8 Marks)
1. Normalization Level: Star schema uses denormalized dimension tables; Snowflake schema normalizes dimension tables into 3NF hierarchies.
2. Query Performance: Star schema provides faster query execution because queries require only simple single-level joins with the central fact table; Snowflake requires multiple expensive joins across normalized dimension sub-tables.
3. Storage Overhead: Star schema contains data redundancy (e.g., repeated city/state names); Snowflake eliminates redundancy, saving disk space.
4. Maintenance Complexity: Star schema is easier to understand and maintain for business analysts; Snowflake has complex structural dependencies.

Topic 30 & 31: Association Rule Mining Formulations

1. Support and Confidence Formulations for Rule $A \implies B$: $$\text{Support}(A \implies B) = P(A \cup B) = \frac{\text{Count}(A \cup B)}{|D|}$$ $$\text{Confidence}(A \implies B) = P(B \mid A) = \frac{\text{Support}(A \cup B)}{\text{Support}(A)} = \frac{\text{Count}(A \cup B)}{\text{Count}(A)}$$ A rule is Strong if $\text{Support} \ge \text{min\_sup}$ and $\text{Confidence} \ge \text{min\_conf}$.

Topic 32: Correlation Measures & The Lift Metric [UPLOADED PYQ]

Lift Correlation Formula [UPLOADED PYQ — IT426 Mid]: $$\text{Lift}(A \implies B) = \frac{P(A \cup B)}{P(A) \cdot P(B)} = \frac{\text{Confidence}(A \implies B)}{\text{Support}(B)}$$
  • $\text{Lift} > 1$: Positive correlation ($A$ and $B$ occur together more frequently than expected by chance).
  • $\text{Lift} = 1$: Statistical independence (no correlation between $A$ and $B$).
  • $\text{Lift} < 1$: Negative correlation (the presence of $A$ discourages the occurrence of $B$).

Topic 34: The Apriori Algorithm (Join & Prune Steps) [UPLOADED PYQ]

The Apriori Property & Pruning Theorem (Agrawal & Srikant, 1994)

Apriori Invariant: All non-empty subsets of a frequent itemset must also be frequent.

Anti-Monotonicity Pruning Rule: If an itemset is infrequent, all of its supersets are guaranteed to be infrequent and can be immediately pruned without scanning the database!

  1. Join Step: $C_k$ candidate itemsets are generated by joining $L_{k-1}$ with itself ($L_{k-1} \bowtie L_{k-1}$).
  2. Prune Step: Any candidate $c \in C_k$ is deleted if any of its $(k-1)$-subsets is not present in $L_{k-1}$.

Q1. [UPLOADED PYQ — IT426 Mid] Compare the significance of Support and Confidence in association analysis. Why is Lift necessary? (8 Marks)
- Support: Measures how frequently an itemset appears across the entire dataset ($P(A \cup B)$). It filters out statistically insignificant random noise.
- Confidence: Measures the conditional reliability of the inference rule ($P(B \mid A)$). High confidence means $B$ is likely when $A$ occurs.
- Why Lift is Necessary: Support and Confidence alone can be deceptive. For example, if 90% of all customers buy Tea ($P(\text{Tea})=0.9$) and rule `Coffee => Tea` has 80% confidence, Coffee actually decreases the likelihood of buying Tea! Lift computes $\frac{0.80}{0.90} = 0.89 < 1$, exposing the negative correlation that Confidence hid.

Topic 37 – 40: Advanced Pattern Mining Methodologies

Advanced Mining Paradigm Algorithmic Mechanism & Description Key Benefit / Example
1. Multilevel Association Mines rules across different concept hierarchy levels (e.g., `Milk => Bread` vs. `Dairy => Baked Goods`). Uncovers granular patterns at lower levels and generalized trends at higher levels.
2. Multidimensional Association Involves multiple predicates or dimensions (e.g., `age(X, "20..29") ^ income(X, "50K..60K") => buys(X, "Laptop")`). Discovers rich customer demographic profiles beyond simple single-item co-occurrences.
3. Constraint-Based Mining Pushes user-defined constraints (Antimonotonic, Monotonic, Succinct) directly into the mining algorithm. Massively prunes the candidate search space; produces only actionable, relevant rules.
4. Closed vs. Maximal Patterns • Closed Itemset: An itemset $X$ is closed if no proper superset has the same support.
• Maximal Itemset: An itemset $X$ is maximal if no proper superset is frequent.		 Compresses millions of frequent itemsets into compact loss-less or lossy representations.

⭐ PYQ-CRITICAL BLOCK A: Classification Algorithms [UPLOADED PYQ]

1. Naïve Bayesian Classification [UPLOADED PYQ — IT426 End]:

$$P(C_i \mid \mathbf{X}) = \frac{P(\mathbf{X} \mid C_i) P(C_i)}{P(\mathbf{X})} = \frac{P(C_i) \prod_{k=1}^n P(x_k \mid C_i)}{P(\mathbf{X})}$$ Class-Conditional Independence Assumption: Assumes that the effect of an attribute value on a given class is completely independent of the values of other attributes.

2. Backpropagation Neural Network Learning [UPLOADED PYQ — IT335 End]:

$$w_{ij} \leftarrow w_{ij} + \Delta w_{ij} = w_{ij} + (l) \text{Err}_j O_i$$ - For output layer neuron $k$: $\text{Err}_k = O_k (1 - O_k)(T_k - O_k)$ - For hidden layer neuron $j$: $\text{Err}_j = O_j (1 - O_j) \sum_k \text{Err}_k w_{jk}$

⭐ PYQ-CRITICAL BLOCK B: Clustering Algorithms [UPLOADED PYQ]

Algorithm [UPLOADED PYQ] Clustering Paradigm Algorithmic Principle Key Advantages & Tradeoffs
1. K-Means [UPLOADED PYQ] Partitioning (Centroid-based) Iteratively assigns objects to nearest mean centroid $\mu_j$ and recalculates centroids to minimize $SSE = \sum \sum \|x - \mu_j\|^2$. Fast $O(t k n)$; sensitive to noise and outliers; requires $k$ upfront.
2. PAM (K-Medoids) [UPLOADED PYQ] Partitioning (Medoid-based) Uses actual representative data points (medoids) instead of mean averages. Iteratively evaluates quality swaps. Highly robust to noise and outliers; computationally expensive $O(k(n-k)^2)$.
3. DBSCAN [UPLOADED PYQ] Density-Based Grows clusters from high-density core points ($\ge \text{MinPts}$ within $\epsilon$-radius). Marks sparse points as noise. Discovers arbitrary-shaped clusters; immune to noise; doesn't require $k$ upfront.
4. BIRCH [UPLOADED PYQ] Hierarchical (Feature Tree) Builds an in-memory CF-Tree (Clustering Feature Tree) where each node contains $CF = (N, \mathbf{LS}, SS)$. Linearly scalable $O(n)$ for massive datasets with single scan of disk.

Q1. [UPLOADED PYQ — IT335 End] Explain DBSCAN clustering algorithm with core points, border points, and noise points. (8 Marks)
DBSCAN relies on two parameters: radius $\epsilon$ and density threshold $\text{MinPts}$:
1. Core Point: A point $p$ is a core point if $|N_\epsilon(p)| \ge \text{MinPts}$ (at least $\text{MinPts}$ points lie within distance $\epsilon$).
2. Border Point: A point $q$ is not a core point, but falls within the $\epsilon$-neighborhood of some core point $p$.
3. Noise Point: Any point that is neither a core point nor a border point.
Clustering: Connects all density-reachable core points into clusters and assigns border points to their adjacent core clusters.
